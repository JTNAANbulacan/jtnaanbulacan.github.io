Before deploying the development branch:
1. Take a current Supabase database backup and verify it can be restored.
2. Review and apply supabase/worship-permissions.sql. It backfills active existing members with their previous operational access and leaves newly registered accounts with no operational permissions.
3. Deploy supabase/functions/worship-access/index.ts as the worship-access Edge Function. The config explicitly requires a valid JWT.
4. Deploy the static site from the development branch only after steps 2–3 are complete.
5. Test login, temporary-password reset, registration, Super Admin account management, each permission, Hub and Presenter live control, monitor/vocalist/instrumentalist views, background selection and sign out.
6. Only after verification should the development branch be merged into main.

Rollback:
- The original repository snapshot is preserved in backup/pre-jtnaan-unification-2026-11-20.
- To restore the original website, return the Pages source to main or restore the backup snapshot.
- Do not roll back Supabase by deleting accounts or storage objects. Any later database rollback must be a reviewed migration that preserves new user records and uploads.
